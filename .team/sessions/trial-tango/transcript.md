## Decisions

- (discovery, 佐藤 美咲 (pm)) 生徒向けは、登録なし・広告なし・片手で操作できることを前提にする。1日抜けても進捗が「ゼロに戻る」設計にはしない。連続記録で責めない。
- (discovery, 佐藤 美咲 (pm)) 先生向けの価値は「採点の手間を減らす」ことと「つまずく生徒を早く見つける」ことの2つ。最初のリリースでは採点の手間削減を優先する。
- (discovery, 佐藤 美咲 (pm)) 生徒の氏名と成績は外部に置かない前提で検討する。先生の端末内、または匿名・ニックネームで扱う案を優先する。管理職の許可が要るものは、最初のリリースの範囲に入れない。
- (planning, 佐藤 美咲 (pm)) 最初のリリースはサーバーを持たない静的 Web アプリにする。データは端末内 (localStorage) とリンク内のデータだけで扱う。理由: 個人情報を外に置かず、管理職の許可を不要にするため。トレードオフとして、端末をまたぐ同期はできない。
- (planning, 佐藤 美咲 (pm)) 単語帳はアプリに同梱しない。先生が貼った単語リストを使う。理由: ターゲット1900は著作物で、先生が毎週30問を作っているため。
- (planning, 佐藤 美咲 (pm)) 進捗は「覚えた単語数」の累計で見せる。1日抜けても減らさない。連続記録、ランキング、他の生徒との比較は作らない。
- (planning, 佐藤 美咲 (pm)) T5 を最優先にする。T5 は田中さんが先に作る。T1〜T4 はその関数を呼ぶ。そのため T2 と T4 は T5 が終わってから始める。T1 と T3 の画面は、型を先に合わせて並行で進める。理由: 全タスクが共通部分に依存するため。
- (planning, 佐藤 美咲 (pm)) T5 のインターフェースは、鈴木さんの案で決める。`parseWordList` は `{words: {en, ja, key}[], errors: {line, reason}[], truncated: boolean}` を返す。`key` は英語の綴りを小文字にして trim したもの。`decodeTest` は例外を投げず、`{ok:false, reason}` を返す。切れたリンクの理由は、生徒に見せる文言にできる形にする。
- (planning, 佐藤 美咲 (pm)) T1 の受け入れ条件に次を足す。「進捗をコピー」「進捗を貼って復元」を学習画面から1タップで届く場所に置く。文言は責めない。書き出したコードを貼ると、覚えた数が元に戻る。復元は足し合わせ方式で、古いコードを貼っても数は減らない。「覚えた」は単語の key ごとに持ち、リストを入れ替えても累計は減らさない。理由: iPhone の Safari は7日開かないとデータが消えるため、ひなたさんのような生徒に直撃する。
- (planning, 佐藤 美咲 (pm)) 結果コードは改ざん防止をしない。チェック4文字は、コピーミスや切れを見つけるためだけに使う。画面や README に「改ざん防止」とは書かない。理由: サーバーがないので防げない。小テストなら、先生が本人の前で確認する運用で足りる。トレードオフとして、点数の書き換えは技術的には防げない。岡田先生が困るなら次回に見直す。
- (planning, 佐藤 美咲 (pm)) 日本語の欄に複数の意味がある場合は、入力式では書かれた意味のどれか1つに合えば正解にする。意味の区切りは「、」とする。4択では全文を1つの選択肢にする。CSV は BOM つきの UTF-8 にする。ニックネームが `=` `+` `-` `@` で始まるときは、先頭に `'` を付ける。単語が4つ未満のリストは、入力式に自動で切り替える。理由: 採点を減らす目的を優先し、判定を厳しくしないため。岡田先生が違うと言えば直す。
- (planning, 佐藤 美咲 (pm)) 「完了」にする前に、実機のスマホで確認する。確認する点は、360px 幅、親指が届く下半分、30問のテストリンクを LINE で送って開けること。ボタンは44px以上にする。キーボード操作にも対応する。
- (planning, 佐藤 美咲 (pm)) T5 の追加仕様を採用する。`encodeTest` / `decodeTest` は async、他は同期。テストIDは単語の内容から作る6文字のハッシュ。ニックネームは `-` と改行を除いて12文字まで、空なら「名無し」。`errors.reason` と `decodeTest` の `reason` は、先生・生徒にそのまま見せられる文言にする。理由: 同じ問題なら集計が分かれず、画面側の二重処理も要らないため。
- (planning, 佐藤 美咲 (pm)) 30問のリンク長が1500文字を超えたら、田中さんがその時点で相談する。進捗保存の関数は画面と分け、T3 のやり直しからは呼ばない。T1〜T5 の内容と担当は、このまま変えずに進める。
- (review, 佐藤 美咲 (pm)) 配布は静的ホスティング (GitHub Pages) に置き、https の URL を先生に渡す方法にする。`file://` で開く運用はしない。理由: LINE から開くには https が要り、ES モジュールは `file://` で動かないため。データはリンクと端末の中だけにあり、サーバーには送らない。トレードオフとして、学校のフィルタで止まる恐れがある。岡田先生に、校内の PC で URL が開けるかを最初に確認してもらう。手順は次の回で田中さんが README に書く。
- (review, 佐藤 美咲 (pm)) T1〜T5 は「ユーザーに見せられる状態」とする。TASK_DONE にするのは、実機 (iPhone Safari・Android)、LINE で30問のリンクを開くこと、Excel での文字化けの3点を確かめてから。T4 で別のテストのコードが「コピーミス」と出る件は、今回は直さない。先生が困ると言えば直す。
- (acceptance, 佐藤 美咲 (pm)) 結果コードと CSV に「組・出席番号」を入れる。本名は求めない。理由: ニックネームだけでは成績簿と照らし合わせられず、採点を減らす目的が果たせないため。番号なら校内の扱いで済むと岡田先生が確認している。トレードオフとして、結果コードの形式が変わるので、今回のコードとは互換を持たない (まだ配っていないので問題ない)。
- (acceptance, 佐藤 美咲 (pm)) 結果コードは、生徒が学校の Google フォームに貼り、先生が回答の列ごと集計画面に貼る運用にする。理由: LINE で110人分が個別に届くのを避けるため。学校ですでに使っている手段なので、新しい許可が要らない。トレードオフとして、組・番号と点数が Google のフォームに載る。岡田先生が困ると言えば見直す。
