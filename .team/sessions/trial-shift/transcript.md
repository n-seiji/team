## Backlog

- T1 [done] owner=eng-backend 希望とスタッフの保存・一覧API
    acceptance: - スタッフ(名前、時給、週上限時間は任意)を登録・編集できる。
    - 月ごと・スタッフごとに、日付別の希望(入れる/入れない、時間帯の一言メモ任意)を保存できる。同じ人が再提出したら上書きされる。
    - 提出に成功すると、受付日時付きの応答が返る。保存に失敗した場合はエラーを返し、受付済みにならない。
    - オーナー向けに、指定月の全員分の希望を日付×スタッフの一覧で取得できる。メモや事情も含まれる。
    - サーバーを再起動しても、保存済みの希望とスタッフが消えない。
    result: スタッフの登録・編集、希望の保存と一覧、受付日時の返却、再起動後も残る保存まで実装済みです。
    - ファイルは `src/app.js`、`src/store.js`、`server.js`、`test/api.test.js` です。
    - 保存は JSON ファイルに一時ファイル経由の rename で書きます。
    - 実行は `OWNER_PASSPHRASE=xx node server.js` です。テストは `npm test` で、全21件が通ります。
    - テストで確認している内容は次のとおりです。
      - 未提出は 200 で `submitted:false` を返す。
      - 提出成功で `receivedAt`(+09:00)を返し、再提出は上書きになる。
      - 保存に失敗するとエラーを返し、旧データが残る。
      - サーバーを再起動しても、スタッフと希望が残る。
      - オーナー一覧は、未提出の人を `submittedAt:null` で含み、メモも返す。
      - オーナー用 API は、合言葉がなければ 401 を返す。
    - 名前選択のみで認証しないリスクは、README の「既知のリスク」に明記しました。
- T2 [done] owner=eng-backend 週上限と人件費率の計算
    acceptance: - 月のシフト案(日付、スタッフ、開始・終了時刻)と、月の売上見込み、人件費の目標率(初期値30%)を渡すと、人件費の合計と売上見込みに対する率を返す。
    - 週上限が設定されたスタッフについて、月曜始まりの週ごとの合計時間を出す。上限を超える週があれば、スタッフ名と該当週を返す。
    - 上限が未設定のスタッフは超過判定の対象にしない。
    - 例: 時給1,100円で5時間なら5,500円。週に22時間入っていて上限28時間の人に6時間追加すると、超過としてその週が返る。
    result: 人件費と週上限の計算は、純関数 `src/calc.js` に置き、`POST /api/calc` で返します。
    - 返す内容は `totalCost`、`rate`、`targetRate`、`diffPoints`、`overLimit` です。`overLimit` は staffId、name、weekStart、hours、limit を持ちます。
    - 週は月曜始まりで、月初の週の前月分は任意の `carryIn` で受けます。
    - 上限が未設定のスタッフは、超過判定の対象にしません。
    - `test/calc.test.js` で、時給1,100円×5時間=5,500円と、22時間+6時間で28時間上限を超える週の2ケースを検証しました。不正入力は 400 を返します。

## Decisions

- (planning, 佐藤 美咲 (pm)) 今回のスコープは「希望の一元回収」「受付確認表示」「組みながらの人件費・週上限チェック」の3つだけ。シフト自動生成、LINE連携、代役探し、結果の早期公開は対象外。週上限は全員共通にせず、スタッフごとの任意項目とする。
- (planning, 佐藤 美咲 (pm)) 名前選択のみでログインは今回作らない。スタッフ用 API は id と名前だけを返し、時給と週上限は含めない。オーナー用 API は合言葉(ヘッダ)必須とする。他人の名前を選べば希望が見えるリスクは README に明記する。
- (planning, 佐藤 美咲 (pm)) 週の計算は `POST /api/calc` の1か所に置き、月初の週の前月分は任意の `carryIn` で受ける。渡されなければ 0 とし、画面に「月初の週は前月分を含まない」と出す。時刻は同じ日の HH:MM のみで、日またぎと休憩控除は今回対象外とする。
- (planning, 佐藤 美咲 (pm)) 依存は 0(Node 標準ライブラリのみ、素の HTML/JS/CSS を `public/` から静的配信)。保存は一時ファイルに書いてから rename する JSON ファイル。API の形は田中さんの README を先に確定し、テストは実装より先に書く。
- (review, 佐藤 美咲 (pm)) 組んだ表のサーバー保存は今回の範囲外。大野さんに「いつもどの端末で組むか」を聞き、複数端末なら次回の最優先にする。

## Verdicts

- iteration 1 · 大野 健二 (user-owner) · **accept** — 打ち直しが要らなくなることと、組みながら人件費率と週上限が見えることは、私の一番の困りごとに効きます。月額の高いサービスでもなく、スマホでも使えそうです。次回は条件つきです。
1. 組んだ表を保存して、別の端末でも開けるようにする。
2. 売上見込みを前回の値で残す。
3. 月の人件費が、画面を開いてすぐ分かるようにする。
- iteration 1 · 陳 美玲 (user-student) · **accept** — 希望を出したあとに「届いた」と分かるのが、いちばん困っていたところです。そこが直っているので、受け入れます。店長に言いにくいことも、画面なら気を使わずに出せます。次回に希望するのは3つです。
1. 提出のあと、その内容を見返せること。
2. 結果のシフトを、早めにスマホで見られること。
3. 自分の週の時間が分かること。
あと、名前を選ぶだけだと、他の人に自分の希望を見られるかもしれません。それは少し心配です。
