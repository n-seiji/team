## Decisions

- (planning, 佐藤 美咲 (pm)) v1は「クライアント登録＋自動採番＋税・源泉計算＋MD/HTML出力」のみ。EUR換算・売上表連携・PDF・外部サービス連携はやらない。理由：事故の原因（前回コピー・番号重複・計算不信）に直結するものに絞るため。トレードオフ：Danielさんの転記と換算の手間は残る。
- (planning, 佐藤 美咲 (pm)) コマンドは `init` / `client add` / `new` / `list` の4つで確定。私の「3つ以内」は撤回する。理由：初回の迷いを減らすほうが、コマンド数を1つ減らすより効果が大きいため。トレードオフ：ヘルプに載る項目が1つ増える。ただしヘルプは1画面に収める。
- (planning, 佐藤 美咲 (pm)) 金額は整数円で持つ。源泉は「報酬のみ」に10.21%を掛けて円未満切り捨てとし、丸め規則をREADMEとテストに明記する。請求書は発行時にスナップショット保存する（宛名・源泉有無・インボイス番号）。理由：計算不信と、過去の請求書が変わる事故を防ぐため。トレードオフ：切り捨てか切り上げかは山田さんの先生に確認が取れるまで暫定。
- (planning, 佐藤 美咲 (pm)) 確認画面でNまたはEnterのみの場合は何も保存せず、番号も消費しない。理由：欠番を出さないため。
- (acceptance, 佐藤 美咲 (pm)) 最終イテレーションは次の3点に絞る。(1) 初心者向けの案内：引数なしで質問に答えるだけで進む形、日本語の手順書、印刷見本。(2) クライアントごとの定番明細の再利用。(3) `list --csv`。GUI、ダブルクリックのアプリ、EUR換算、売上表連携はやらない。理由：ブリーフの「ターミナルから」を守りつつ、事故の原因に近いものと、初回で離脱する原因だけを直すため。トレードオフ：山田さんには今回も、Node.js を入れる手間が残る。
- (planning, 佐藤 美咲 (pm)) `new` と `client add` は鈴木さん、`list --csv` と core(`getTemplate`/`setTemplate`/`invoicesToCsv`)は田中さんが触る。定番の下書きは「採用/修正/最初から入力」で Enter は採用、確認画面は必ず通す。保存済みと同じ内容なら「定番にしますか？」は聞かない。CSVはUTF-8 BOM・CRLF・先頭が `=+-@` の値は `'` を付ける。理由：ファイル衝突を避け、Excelでの事故を防ぐため。トレードオフ：CSVの値の先頭に `'` が付くことがある。
- (acceptance, 佐藤 美咲 (pm)) v1 は「ターミナルを使える個人事業主」向けに出す。山田さんのような非エンジニアには、導入を手伝う人がいる前提で案内する。理由：ブリーフが「ターミナルから」であり、最小のスコープを守るため。トレードオフ：山田さんは今回 reject のまま残り、A4 の実機確認、導入を含めた所要時間、JSON 出力、源泉の丸めは次回に持ち越す。
