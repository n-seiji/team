# trial-care

遠くに住む親が朝の薬を飲んだことを、ボタン1回で記録し、家族がそれを見られるようにする小さなサーバー。
Node.js 22.18 以上のみ。実行時の依存はありません。

## 動かし方

    npm start            # または: node src/main.ts
    npm test

起動すると、本人用と家族用の URL が表示されます。

    本人用: http://127.0.0.1:3000/m/<長いランダム文字列>/
    家族用: http://127.0.0.1:3000/f/<別の長いランダム文字列>/

| 環境変数 | 既定 | 意味 |
|---|---|---|
| `PORT` / `HOST` | 3000 / 127.0.0.1 | 待ち受け。外に出すときは `HOST=0.0.0.0` と HTTPS の入口(リバースプロキシ)を用意する |
| `CARE_DATA_DIR` | `./data` | 記録(`records.json`)とトークン(`tokens.json`)の置き場所。バックアップ対象 |
| `CARE_MOTHER_TOKEN` / `CARE_FAMILY_TOKEN` | 自動生成 | 20文字以上の英数字と `-` `_`。未設定なら生成して `tokens.json` に保存し、次回も同じ値を使う |

## API (すべて JSON、時刻は日本時間)

| メソッド・パス | 返り値 |
|---|---|
| `POST /m/<t>/taken` | `{"taken":true,"date":"2026-10-17","at":"06:42"}` 初回も2回目も同じ形。`at` は最初の押下の時刻 |
| `POST /m/<t>/taken?date=2026-10-16` | 「あとから飲んだ」。その日の記録として保存し、`at` は押した時刻。`date` は今日と過去3日だけ(それ以外・不正な値は 400 で記録しない)。2回目以降は最初の時刻を保持 |
| `GET /m/<t>/today` | 記録あり `{"taken":true,"date":…,"at":"06:42"}` / なし `{"taken":false,"date":"2026-10-17"}` |
| `GET /f/<t>/status` | `{"today":{…},"days":[…]}`。`days` は今日を除く過去3日、古い順に3件固定。記録のない日は `{"date":…,"taken":false}` |
| `GET /m/<t>/` , `GET /f/<t>/` | `public/m.html` , `public/f.html` |

- トークン違い、本人用と家族用の取り違えは 404。メソッド違いは 405。末尾スラッシュなしの `/m/<t>` は `/m/<t>/` へ 308 リダイレクト。
- 「今日」は常に Asia/Tokyo 基準(サーバーのタイムゾーンに依存しない)。日付が変わると「まだ」に戻る。
- 1日1件の記録。朝・昼・夜の区別も、朝かどうかの判定もしない(夕方に押しても記録する)。
- 同じ日の2回目以降は最初の時刻を保持する。保存は一時ファイルに書いてから置き換える。`records.json` が壊れていると、記録を消さないために起動時に失敗する。

## 知っておくこと(リスク)

- ログインがないので、**URL を知っている人は誰でも見られる(本人用は記録もできる)**。LINE 等で送ったら、履歴が残る場所に URL があることになる。漏れたら `data/tokens.json` を消して再起動し、新しい URL を配り直す。
- HTTP のままインターネットに出さない。URL が通信経路に平文で流れる。
- 単一プロセス前提。複数プロセスで同じ `records.json` を共有しない。
